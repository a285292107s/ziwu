踩坑清单：每条按「症状 → 根因 → 防线」写，改到某个模块之前、或看到某个现象觉得「应该不至于」时先来这里查一遍。

## 天光与海面

### 水面上有波纹也有焦散，能量却摊错了通道
- 症状：画面看着正常，波纹与焦散都在，单看画面发现不了；只有 CPU 侧逐通道对照才露出能量摊错了位置。
- 根因：半区长写成从大到小，那是 DIF 的顺序；DIT 蝶形（twiddle 乘在 b 上、取 a±bw）要求半区长从小到大。两者混用得到的仍是酉变换，总能量守恒、画面不崩，只是能量被摊到错的通道。
- 防线：FFT 的打包顺序只能靠 CPU 侧逐通道对照判对错，不要凭「有波纹、有焦散」下结论。

### 水面像一层几乎为零的起伏
- 症状：实测斜率均方根小到水面几乎是平的，看不出是少了哪一步。
- 根因：蝶形是未归一化的逆变换，写进纹理前还要除 N²，方差里因此带着 1/N⁴；漏掉它整片水面被缩掉好几个数量级。
- 防线：CPU 侧解析预期与 GPU 回读对照是唯一抓得住它的办法，波高、斜率、拉普拉斯三项都要与解析预期对上。

### 水面浮着一层细噪点，找不到是哪一步错的
- 症状：水面有一层细噪点，逐项排查都像是对的。
- 根因：`half-float` 超过 65504 直接溢出，大数上还会丢低位，而 FFT 的中间量恰好在这个量级，蝶形于是在无声处丢精度。
- 防线：FFT 的中间 target 一律 32F；只有最终那张主纹理可以降到 16F，它数值范围小，而且 16F 才开得了 mipmap。

### 波形镜像，光柱从错误的一侧斜过来
- 症状：波形相位整体镜像，直射光柱的倾斜方向反了；不报错，只是物理方向不对。
- 根因：演化式要的是 `conj(h0(−k))`（虚部取反），存成 `h0(−k)` 就得到镜像的相位。
- 防线：打包约定（`uSign`、位反转、输出自然序）必须逐项验算；回读诊断看的是统计量，方向错了它不会报。

### 日落下半幅变成一片薄荷绿
- 症状：压低浅色主题的曝光目标后，水体确实暗了，但整幅被推进 ACES 中段，日落的画面下半幅是一片薄荷绿（试过更低，已回退）。
- 根因：ACES 中段色相是饱和的；明暗层次本来由吸收决定，窗、水体、沙面各走不同水程，曝光只决定这三段落在线性段的哪个位置。
- 防线：想要更亮的窗就让窗本身更亮，不要靠压曝光买层次。

### 构建打印成功，着色器其实被截在半句上
- 症状：构建照常打印「生产构建完成」，页面里的着色器却缺了后半段，只有 `typecheck` 报得出来；这个坑在本项目踩过两次。
- 根因：GLSL 写在 TS 模板字符串里，注释中出现一个反引号就把模板字面量截断，而构建对字符串内容不做语法检查。
- 防线：着色器一律放 `.glsl` 文件、用 Vite 的 `?raw` 导入，不要因为「只是几行」就写回模板字符串；`.glsl` 里不能自己写 `#version`，属性声明按材质类型决定。

### 自适应分辨率一路涨到上限，看起来性能很好
- 症状：分辨率涨到上限并停住，像性能很好；另一种表现是交付帧率恰好是刷新率的一半，60Hz 上永远看不到；软件光栅化下 GPU 计时还能拿到恒为 0 附近的伪值。
- 根因：WebGL 绘制是异步提交，提交耗时里根本没有 GPU 开销；rAF 间隔跟着刷新率走，刷新率接近目标帧率时每次回调都差一点点，于是一律跳过、下一次才画。
- 防线：主信号用两次真实绘制之间的墙钟间隔（它含 GPU 反压），提交耗时只用来抓主线程卡顿；跳帧按 vsync 计数；GPU 计时低于物理下限就当没测到，不拿提交耗时冒充。

### 着色器编译失败，画面是一块纯黑
- 症状：用户看到「背景瞎了」，而不是退回 CSS 兜底。
- 根因：three.js 编译或链接失败时只往 console 打日志，然后照常出图。
- 防线：初始化时主动 `compile` 一次并检查程序是否可运行；判据用 `runnable === false`，不能用「diagnostics 存在」——链接成功但 info log 非空时它也会挂上；CSS 兜底层必须一直垫在下面。

### Snell 窗里是一片没有信息的纯色
- 症状：窗内亮度是个常数，太阳、月亮的位置全对不上。
- 根因：GLSL 的 `refract()` 要求 N 与 I 反向，这里的视线与法线都朝上，算出的折射光线法向分量恒为负、永远朝下；而且全反射时它返回 0，窗沿需要的是连续渐变。
- 防线：手算 `t = eta·I − (eta·cosθi − cosθt)·n`，`cosθt` 截断到 0 继续算，越界部分交给菲涅耳权重压掉。

### 下半幅只剩一条和上半幅无关的暖色带
- 症状：画面下半部分没有体积雾，只剩一条来历不明的暖色带，透过率还大于 1 被放大。
- 根因：对着向下的视线，`(uDepth − uFloorDepth)/dir.y` 给出负数；体积循环第一次就 break，而 `marched >= limit` 反而成立，下半幅于是由「相机背后那个点上的海底」构成。
- 防线：距离求交一律写成「目标面相对相机的位置 / 方向分量」；eye 在 −depth、沙在 eye 下方 floorDrop，所以 `t = −floorDrop/dir.y`，两条候选距离取 min 后谁近谁决定终止面。

### 窗整个跑到画外，画面像一块长焦渐变
- 症状：顶上那片 Snell 窗跑到画外，海底只剩薄薄一条，中间一大片是掠射拉长的倒影，怎么调都像一块渐变。
- 根因：uv 减的是半高（±0.5），`d.z` 却写成 `1.0/tanHalfFov`，等效竖直视场只剩一半，等于把画面裁成了长焦。
- 防线：`d.z` 必须取 `0.5/tanHalfFov`；改 `rayDir` 后拿一条已知俯仰的构图对一遍地板与窗的占比。

### 磁贴栏一带浮着摩尔纹，还随波纹每帧闪
- 症状：低渲染比例下磁贴栏那一带浮一层摩尔纹，并且随波纹逐帧闪。
- 根因：画面下半幅的沙离相机只有两三米，一纹素跨几十厘米，高频那几档连一个完整周期都放不下，采到的是走样不是细节。
- 防线：每一档先按 `fwidth` 问「一个像素还剩几个可分辨的周期」，不到一个就退回均值（`nzFade`），不要靠降低振幅硬压。

## 首帧与主题

### 切过去整幅几乎全黑，或过曝发白
- 症状：主题切换后整幅几乎全黑或过曝发白，稳态截图看不出来，得看切换后的头几帧。
- 根因：增益是有状态的，切换后没有任何东西重置它，而两套主题的深度与曝光差近一个量级。
- 防线：有过渡时先私下画几次终点帧、按量出来的终点走过去；无过渡时用该主题上次收敛的「曝光 × 增益」预置，记增益本身只能当次用。

### html 上是深色，水却还是浅色的
- 症状：html 上有 dark 类、薄膜按深色算，画面却一直是浅色的水。
- 根因：主题从 `chrome.storage.local` 异步读出，挂载那一刻还是默认值，`pushFrame` 按浅色算了一帧，而薄膜每次都读实时的 `props.dark`。
- 防线：`watch(dark)` 里重推一帧，不等定时器；reduced-motion 下还要补一次 `renderOnce`。

### 开了「减少动效」之后，闭环的修正落不到画面
- 症状：reduced-motion 下切主题后画面停在上一主题，或曝光一直错着，直到窗口尺寸变化之类的偶然事件才触发一次。
- 根因：只画一帧的路径里，探针把 `gainTarget` 改了，但没有下一帧去用它。
- 防线：`renderOnce` 里比较 `gainTarget` 与 `gainShown`，差得多就再画一帧；顺便补上那次翻牌，否则 canvas 一直停在透明。

### 整段过渡是「闪一下」，不是「沉下去」
- 症状：过渡读起来是闪一下（上一版单帧跳变就有终值的 85%）；沙面那头是硬切、藏在过渡两端（上一版取 `max()` 时浅→深整段沙停在近处、结束那帧才归零，单帧整幅均值变化 46%）；薄膜那头是切换瞬间的一下白闪。
- 根因：透过率按 Beer–Lambert 走指数，参数均匀地走、亮度却会在中段一头扎下去；「有底 / 没有底」在参数空间里是断点，线性插不过去。薄膜的白闪来自两处：过渡中文字颜色正走在半路，中间色需要的对比度比两端都高；雾按探针测到的画布亮度驱动，画面变亮是逐次探针出来的，雾退得比水慢。
- 防线：过渡用 smootherstep、比页面入场慢一档；把「没有底」当成一个很远的底，让距离连续走过去；终点曝光实测、过渡期间闭环不参与；薄膜在入场与过渡期间把逐元素需求截断到落定后的那一档，深→浅另开快速跟随窗口。

### 深色主题的薄膜长期顶在上限，正文糊成灰
- 症状：薄膜长期顶在上限，正文带糊成一块灰；换文字颜色也救不回来。
- 根因：可读性的约束只在正文带里，驱动薄膜的却是整幅最亮处（Snell 窗），它根本不在正文带里；同类错误还有一次，用正文带的 p90 反推元素局部背景、据此算出「比实际需求低得多」的 alpha 就够，实测直接不达标——p90 在那些位置上低估了局部背景。
- 防线：约束在哪就在哪量，浅色看元素框内最暗处、深色看最亮处，两个主题方向相反；上限只能由最坏那一行的实测值决定。也不要因为「长期顶在上限」就断定它被过度遮罩——那可能只是在补贴正确的东西。

### 矮视口上，设计好的构图落在屏幕外
- 症状：矮视口且页面纵向溢出时，构图有相当一部分落在屏幕外，探针的正文带跟着文档往下挪、和真正的时钟、问候语错开。
- 根因：absolute 的天空跟着文档一起长高，着色器按整个文档高度构图，人却只看得到视口那一块。
- 防线：背景层用 fixed，让画布就是可见视口本身，构图与探针的坐标系同时回到设计值；页面溢出是布局问题，不在背景层职责内。

### 磁贴栏的文字从来没被量过
- 症状：快捷方式标题、拖动提示、整理按钮、站名这一片从没被量过，而深色主题的原始画布在那一带是亮的——亮灰字压在亮背景上等于看不见。
- 根因：那张选择器表就是「可读性约束到底在哪」的清单，没登记的文字不会被探针量，也就没有任何机制保证它读得出来；这一档换文字颜色救不了，要达标所需的文字亮度会超过 1.0，背景必须被压暗。「有自己的玻璃底」也不等于不依赖背景，半透明的玻璃透出来的就是它自己的背景。
- 防线：往页面里加压在背景上的文字时，往那张表里加一行；遍历用 `querySelectorAll` 而不是 `querySelector`——站名横跨整幅，只量第一个会漏掉最坏的那一个。

### 开页头几帧的数据被当成稳态
- 症状：刚打开时水一直不是它该有的清晰度：首帧被当成 CPU 瓶颈砍一档分辨率，开页窗口又被当成 GPU 瓶颈再砍一档；拿去评审的低分辨率帧里水面波纹消失、镜面窗退成一块过曝白，追着改镜面亮度、日轮月轮都没用。
- 根因：那几帧挤着一次性工作——着色器编译链接、波场标定的阻塞回读、图标取色，再加上分辨率与曝光的爬坡；它们描述的是启动，不是稳态。着色器里还有按屏幕分辨率走的高频淡出，低分辨率下高频本来就少。
- 防线：热机窗口内不记提交耗时、不累计帧率窗口、不触发自适应，窗口内照常跑曝光闭环的密集探测；取图等控制器自报稳态，不写死毫秒。

## 磁贴与站点

### 点磁贴图标毫无反应，控制台也不报错
- 症状：点磁贴图标毫无反应，控制台不报错；拖完松手又会顺手打开站点；慢按一下再松手也什么都不发生。
- 根因：在 `pointerdown` 里 `setPointerCapture` 之后，这次手势随后的 `mouseup` / `click` 也会被重定向到被捕获的格子（`li`），而磁贴是里面的 `<a>`，链接默认行为从不触发；目标在派发时就定了，事后 `releasePointerCapture` 救不回来。
- 防线：捕获只在真正开始拖之后做；「按住但没挪窝」那次点击由组件手工补发（同标签页，Ctrl/⌘ 开新标签页）；拖过的那一格单独挡一次 click；验证阈值两侧都要跑，并在捕获阶段记下每次点击实际落到了哪个元素。

### 撤销提示出现在磁贴带底部，下拉被磁贴盖住
- 症状：撤销提示出现在磁贴带底部而不是视口底部；搜索框的引擎下拉被后面的磁贴盖住，截图里能看到磁贴从菜单里透出来。
- 根因：`animation ... both` 结束后仍保留「已结束」的 `transform`，而带 transform 的元素会自成一格层叠上下文、并成为 `position: fixed` 后代的包含块。提示挂在整块磁贴带里就被钉在带的底部；搜索框的入场动画曾挂在 `.search-root` 上，它内部的下拉于是再也压不过磁贴。
- 防线：浮层一律 Teleport 到 body；入场动画挂到没有子级浮层的节点上（胶囊而不是整块搜索框）；菜单的层级仍要显式高于磁贴带。

### 删光磁贴再加回来，空状态和「+」格又演一遍入场
- 症状：删光最后一条快捷方式再加回来，空状态与「+」格会把入场阶梯又演一遍，和用户刚做的事无关。
- 根因：波是否起过是永久为真的，而这两块都在 `v-if` / `v-else` 里、会被销毁重建；重建时它们看到「已经起过波」反而又拿到一次入场。
- 防线：起波那一刻把参演名单定死，之后谁被销毁就把名额收回；新来的磁贴走另一套「立刻落位」的短动画，不再排队。

### 同一份构建，每次打开磁贴带的起波时刻都不一样
- 症状：连续打开时起波落在首帧之后几十到上百毫秒的随机位置，正好压在问候与搜索框那两拍上；更糟时会先看到一屏种子站，再闪成用户自己的磁贴。
- 根因：起波直接接在 `shortcutsReady` 的 resolve 上，时间轴由 storage 的往返决定；挂载那一刻渲染的是 `defaultShortcuts()` 的种子站，异步回来后整份列表被换掉，两轮各自入场就是「两波」。
- 防线：磁贴带由自己的幕布遮到真列表就位，起波取「数据就绪」与 hero 节拍锚点的较大者；兜底定时器只防「storage 永不返回」这一种病，不属于编排。

### 点空白再按 Tab，落点取决于点在哪
- 症状：点搜索框以外的空白再按 Tab，有时落到问候语、有时落到设置，同一个动作给出不同落点。
- 根因：浏览器把焦点留在 `body` 上，下一次 Tab 从点击位置继续，落点由点击位置决定。
- 防线：焦点不在任何控件上（`body` / `documentElement`）时，Tab 与 Shift+Tab 先回到搜索框；这条路径要靠一个「正在恢复焦点」的标记跳过首站接管，否则会把一次性的首站名额白白用掉。

### 一排磁贴全显示同样的灰色地球
- 症状：一排磁贴全显示同样的灰色地球，`<img>` 的 `onerror` 永远不触发，首字母回退失效。
- 根因：MV3 的 `/_favicon/` 对 Chrome 图标库里没有图标的站点返回通用占位图，而不是 404。
- 防线：用一个保证不存在的域名（`.invalid` 保留域名）要一张图，运行时标定它的像素指纹，之后每个站点算同一指纹并与它比对，相同或几乎全透明就判为无图标；指纹必须运行时标定，不能写死——Chrome 版本或平台换了占位图就会漂。

### 占位地球照旧显示，检测像没生效，控制台却什么都没有
- 症状：占位地球照旧显示，检测看起来完全没生效，控制台没有任何报错。
- 根因：标定探针和真实图标都接收「已经拼好的图标地址」，早期接口把「站点地址」与「图标地址」并排成两个参数，调用时传错，标定拿到的是无法解析的地址，指纹为 null。
- 防线：入口收窄成只收站点地址，由内部统一拼图标地址；两个参数并排的 API 迟早会被传反。

### 刚缓存好的真图标退回成首字母
- 症状：多开几个新标签页或会话恢复拉起多个页面后，某个站点刚缓存好的真图标退回成首字母，仿佛缓存没写进去。
- 根因：每个新标签页、侧边栏、设置页都是独立的扩展页面，各自持有一份内存镜像；后写的页面拿加载时的旧镜像整份覆盖，会抹掉另一个页面刚写入的真图标。
- 防线：每次写入前从 storage 重读最新记录再合并落盘，不拿页面加载时的镜像覆盖；缓存是跨页面共享的可变数据，任何整份写入都要先合并。

### 某个磁贴的图标位置一直是空白
- 症状：某个磁贴的图标位置一直是空白，没有可见报错，也不会自动退回首字母，直到缓存过期。
- 根因：脏数据校验只能拦住前缀不对或超长的串，拦不住前缀合法、内容解不开的 `data:` URL；这种图浏览器解不出像素，只留一个空白 `<img>`。
- 防线：给显示图标的 `<img>` 挂 error 兜底，退回首字母并丢掉那条缓存，下次打开重新判定即可自愈。

### 改了磁贴网址，图标还是上一个站点的
- 症状：在设置页编辑磁贴网址后，新网址上短暂或长期显示上一个站点的图标。
- 根因：图标加载是异步的，加载期间 `pageUrl` 可能已经变了；回调里直接写入结果就会把旧站点的图贴到新地址。
- 防线：`load()` 返回后先比较当前 `pageUrl()` 与发起时的 target，不同就丢弃结果。

## 存储与迁移

### 升级后第一次打开，部分设置回到默认值
- 症状：从旧前缀版本升级后第一次打开，部分设置回到默认值或老数据消失，重开一次又正常。
- 根因：迁移写在读路径，而新键不存在时读逻辑会先写默认值；新标签页与设置页同时首读时，另一个页面可能刚把旧键搬完并删掉，本页读到旧键为空，若不复查就会把默认值写进新键，覆盖刚迁移的数据。
- 防线：旧键读不到时必须再读一次新键（旧键先写后删，所以此时新键必然已有值）；迁移顺序保持「读旧 → 写新 → 删旧」，两步之间失败也不丢数据。

### 点了导出没有下载，或下载出空文件
- 症状：点击导出后浏览器没有下载，或下载出空文件；换个浏览器或时机又正常。
- 根因：`URL.revokeObjectURL` 在点击后立刻执行，部分浏览器还没开始读这个 Blob，链接就失效了。
- 防线：把回收放到下一轮事件循环，让浏览器先接住下载再释放。

## 构建与验证工具

### Windows 上 esbuild 临时文件删不掉，build:web 直接失败
- 症状：`node scripts/rebuild.mjs` 在 `build:web` 阶段报 `[vite:esbuild-transpile] remove C:\Users\...\Temp\esbuild-...: Access is denied`，重试仍然失败。
- 根因：系统临时目录里的 esbuild 临时文件建得出来、删不掉（本机 ACL 或杀软占用），不是 Vite 配置或源码错。
- 防线：把 `TEMP` / `TMP` 指到仓库内的 `.tmp`（已 gitignore）再构建：
  `$env:TEMP = "$PWD\.tmp"; $env:TMP = $env:TEMP; node scripts/rebuild.mjs`。

### 逐行剖面显示背景有横向条带
- 症状：逐行剖面看起来有横向条带，曾被当成删掉直射光柱的依据。
- 根因：量剖面时只藏了薄膜、没有藏掉前景，量到的是钟点、搜索栏下边框和磁贴的起伏；藏掉前景再扫，背景的纵向剖面是一条平滑的渐变。
- 防线：量背景亮度剖面必须把前景一起藏掉；删除结论可以照样成立，但不能拿一次量错对象的测量去支撑它。

### 稳态判据永远返回否，每一帧都判成没稳
- 症状：稳态判据永远返回否，每一帧都被判成「没稳」，而日志里控制器其实还在正常爬坡。
- 根因：扩展页只允许自身脚本、页面里没有 eval，而 Playwright 把谓词投进页面时可能走 eval，报错又被外层的兜底吞成 false，判据于是静默地永远为假。
- 防线：改在 Node 侧用页面求值轮询，既不碰 eval，也能把「为什么没稳」报出来。

### 定格断言报「暂停了 0 条」，每一帧都是终态
- 症状：定格断言报「暂停了 0 条」，每一帧都是落定态，胶片条拍出来全是终态；动画分组表也整张空掉。
- 根因：按 Web Animations 规范，动画只有在活动相、或填充影响它时才算相关；入场动画改用 `backwards` 填充后，一跑完就不再相关，立刻从 `document.getAnimations()` 里消失，连延迟与时长这些静态参数也一起读不到。
- 防线：起波即把动画对象与元数据收进集合并持有引用，命中后再暂停并把当前时间设回活动区间；现场再读一次只作保险。

### 删掉一格之后，报告里多出一批「新动画」
- 症状：删掉一格之后报告里多出一批「新动画」，看起来像删一格让其它格子重新入场了。
- 根因：`getAnimations()` 把 CSS 过渡也一并返回，而过渡没有动画名，读元素当前的计算动画名就会把它读成入场动画、延迟为零。
- 防线：按对象类型区分动画与过渡，过渡单独列在报告里，不参与「重新入场」的证据。

### 新增或删除触发的动画一条没收到，断言却全绿
- 症状：新增或删除触发的动画一条都没收到，断言却全绿。
- 根因：这类动画只存在它自己那几百毫秒里；先变更、等一会儿再开始收集，收集窗口打开时动画早就没了。
- 防线：先让页面开始收集，再在收集窗口内做变更，并加一条「本次收集非空」的自检，为空直接判失败。

### 入场窗口只采到个位数帧，像是页面卡
- 症状：入场窗口只采到个位数帧，很容易被读成页面卡。
- 根因：无头环境里逐帧回调跟着合成帧走，页面一静止就不再回调；标签页被别的辅助页抢走前台时，逐帧回调与计时器会一起被节流——「采到几帧」是这段编排动了多久的函数，不是流畅度的函数。
- 防线：采样页最后创建、置于前台并用 CDP 模拟焦点三道一起上，把实际可见状态写进产物；要跨轮比较主线程占用，只能靠不依赖合成帧的计时器采样。

### 对比度报告全绿，其实一个元素都没量到
- 症状：对比度报告全绿，其实一个元素都没量到。
- 根因：审计项按页面结构写选择器，页面一改就永远查不到元素，而「查不到」被当成了「没问题」。
- 防线：改成显式的「页面 + 选择器」表，查不到的元素单独报出来并计入失败数，不许它伪装成通过。

### 一批本来达标的文字被判对比度不足
- 症状：一批本来达标的文字被判对比度不足，尤其是刚出现入场动画的空状态。
- 根因：入场期间元素透明度还没到 1，而对比度计算会把透明度乘进前景色；固定等一小段正好落在动画中段。
- 防线：先等页面上所有动画结束再量，对无限循环的呼吸动画用超时兜底，不能指望它自己结束。

### 每一行都稳定地偏一个方向，看着像真实漂移
- 症状：每一行都稳定地偏一个方向，很像真实漂移。
- 根因：旧基线抓在天空层还是绝对定位的年代，那时文档比视口高、着色器合成的是一张更高的画，同一批行号对应的其实是画面里更靠上的位置；换合成方式之后旧基线就永久偏移了。
- 防线：合成方式一变就重抓基线，并把「真实漂移」与「基线偏移」分开报告；纵向那三段结构（窗最亮、中段镜面最暗、沙面次亮）在新旧基线里都成立，可以留下来当粗看依据。

### 报告一切正常，每一帧却像浏览器自带的新标签页
- 症状：报告一切正常，但每一帧的颜色与时刻都像浏览器自带的新标签页。
- 根因：无头环境加命令行加载扩展偶发失败，service worker 不注册、新标签页改写不生效，页面根本不是本仓库的产物。
- 防线：起上下文后先验证新标签页改写真的接管——用落地文档的地址判断，不能用浏览器侧记录的标签页地址（那可能是被改写前的请求地址）。

### 悬停一直重试到超时，或者量到的提示是透明的
- 症状：对排序按钮调用定位器的悬停会一直重试到超时；键盘走到按钮上时，提示气泡量出来的不透明度是 0，看起来像键盘路径坏了。
- 根因：这类按钮平时不接收指针事件，只有磁贴进入悬停才恢复，而定位器悬停前会先做命中测试，此时它不可能被命中；脚本调用聚焦又不满足「用户正在用键盘」的判定，焦点可见样式不会生效。
- 防线：按坐标移动鼠标，先移到磁贴本体让它进入悬停，再移到按钮上；要量键盘路径就真的按 Tab 走到目标元素，别用脚本聚焦代替。

### 开发模式下首帧主题失效，生产产物却正常
- 症状：开发模式下首帧主题失效，页面先按系统偏好闪一下，生产产物完全正常。
- 根因：桩页面靠字符串替换把入口脚本指向开发服务器，而同一个标签也写在页面注释里，只匹配文件名会改到注释上，真正的标签留在原地变成 404。
- 防线：替换时连结束标签一起匹配，只改真正的那一段。
