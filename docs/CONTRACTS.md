# 口径与不变量

这里收集子午 Ziwu 的口径与不变量：单位与色彩空间、跨文件必须一致的键与几何约定、统计口径，以及那些违反后不报错、只会悄悄错的约束。违反任何一条都不会让构建失败或抛异常，只会让画面、首帧、磁贴或备份在某条路径上悄悄偏掉，多数要等到一次视觉评审或用户丢数据才被发现。

## 天光与海面

### 天光帧的单位与色彩空间

天光帧里的颜色是线性 RGB，色相类字段已按最大分量归一化成「只有色相」的量，亮度由曝光、增益与各自的强度标量负责（`scatterTint`、`skyAbove` 这类已经把强度乘进去的除外）。距离一律是米、消光与散射是每米系数、角度是弧度、方位角自正北向东为正。把 sRGB 的值直接塞进来不会报错，只会让闭环与薄膜的校准整体偏移。

### 地点近似的精度预算

经度从系统的时区偏移反推而不取真实地理经度，纬度取中纬度默认值，只求太阳大致在本地正午最高——这个画面上最要紧的性质比经纬度准确更值得保。太阳走 NOAA 低精度公式，月亮走 Schlyter 简化模型：月亮位置有一两度的误差，但视直径只有半度、相位只取决于日月距角，所以是准的，不必换成高精度历表。

### 水下主光的方向

直射光与漫射天光的方向都必须从水面折射进来，空气到水永远不会全反射；太阳压到地平线时空气里的光几乎贴着地面走，一进水也被掰到离垂直方向不超过全反射临界角，所以水下不存在近乎水平的光。着色器按 `beamDir` / `ambDir` 的 y 分量为负来用；光源落到地平线下时要退化成漫射天光的方向，不能留一个朝上的向量。

### 正文带与 Snell 窗的同一份契约

从水下抬头，能看到的水面之上的天永远落在以垂直方向为轴、半角为全反射临界角的锥里，锥的下缘固定在全反射临界角的余角仰角处，与太阳在哪、几点钟都无关。浅色主题的相机俯仰是从可读性倒推的：整条正文带必须落在窗里，因为窗是画面里最平滑最亮的区域，带子跨到有波纹的镜面纹理上，曝光探针量到的分位数就会乱跳、闭环跟着抖。改俯仰必须同步改 `skyRenderer` 里正文带的上下界，改带子也必须回头核俯仰。

### floorDrop 的语义

它是相机正下方到沙面的垂直距离，零表示没有底，不是「水面下多少米」也不是相机的绝对深度。把它当深度差去解交点（沙的水下深度减相机深度）会算出沙面在相机上方，每条向下视线的交点距离都是负数，画面下半部分因此是由相机背后的一个点画出来的。

### 天光色与直射光色

头顶那片天是散射光、天生偏蓝，直射光正午接近暖白、压到地平线才变金橙，两条颜色不能合并成一个 tint。合并之后画面上每个像素都是同一个青白色，色相上没有任何分层，剩下的差别会被 ACES 压平——水下的暖色只能从直射光这条路进来，因为水把红光吃得最快。

### 吸收系数与散射系数

着色器要用总消光（吸收加散射）做所有指数衰减，也要用单独的散射系数算「水自己发光」那一项，混成一个系数就丢掉了一整个物理环节——被拐走的那部分本应重新进入视线。总消光的逐通道值同时被两套主题的深度、底板水程与曝光目标带校准过，动它等于同时动亮度、色相与可读性三件事，先想清楚要改的是吸收还是散射。

### scatterNorm 的归一化

它是 σs/σt 按 Rec.709 加权亮度归一后的谱形，加权均值因此为 1，乘上去只改「水自己发的光」比透过的光蓝多少，不改亮度，自动曝光闭环与薄膜的整套校准因此不受影响。它在模块加载时算一次就固定，不要在别处按帧重算或再乘一个系数。

### 相函数不对称因子的上限

水加悬浮颗粒的实测不对称因子可以到很高，但这里不能取到上限。它在画面上的表现只是「顺着光看过去更亮」的一层方向性，给大了会在 Snell 窗那一侧顶出一个亮包，而那片区域正是正文所在的地方。

### 底板与 Snell 窗的水程

水体底光是「从水面下来再沿视线回来」两段水程，系数必须大于一倍相机深度；给不足时画面中段会是一层中性偏白的薄雾，整幅读成冰面或卷云而不是水。透过 Snell 窗看到的天只走水面到相机这一程，系数要接近一倍而不是两倍，多算一倍的代价在日落时最明显——暖橙的天光会被滤成灰紫。

### 曝光的来源与闭环的边界

一天里的变化不走亮度，走色温、Snell 窗的位置和吸收出来的色相；场景里的曝光系数是按「第一帧就已经接近正确亮度」反推的，闭环只负责小幅修正。想让画面更亮就改场景系数，不要去放宽闭环的增益范围——那会让页面打开后的头几秒出现一段从过曝滑下来，而那几秒正是第一眼。深色主题的曝光目标必须随夜色下移，钉在白昼值上夜里的水永远够不着它，增益会被顶到上限、控制器只剩「往上推」一条路，等于退化成单向棘轮。

### 时段界限的唯一真源

`phaseForHour` 是时段划分的唯一出处，`ambience.ts` 的降级调色板 re-export 它。两边各写一套界限时，WebGL 不可用、退到 CSS 渐变时颜色会在时段边界上跳一下，而这种错误只在降级路径上出现；降级调色板跟随真实时间，不受 `?sky=` 评审参数影响——那条参数只钉住 WebGL 天空。

### 波场纹理的两套通道顺序

主着色器采样的那张纹理 R 空置（FFT 打包留下的数学零位，不是预留通道）、G 与 B 是 ∂h/∂x 与 ∂h/∂z、A 是全带焦散；初始化回读的蝶形输出是另一套顺序：x 斜率、空位、负拉普拉斯、z 斜率。按主纹理的顺序去解释回读缓冲不会报错，只会让焦散取错通道、两条斜率对调。

### 波场的取样坐标

取样一律传未取模的世界坐标（乘波场物理边长的倒数），纹理开了 RepeatWrapping，硬件会在接缝处正确跨边界插值。自己 `fract` 反而在缝上造出一条半纹素的硬边。

### 水面斜率的量纲

FFT 谱已按目标斜率均方根归一，纹理里的斜率就是物理斜率，不再乘任何艺术系数。正文带的入射角离水到空气的临界角余量不大，法线倾角均方根一旦超过它，正文带大半像素会被翻到镜面侧，Snell 窗被碎纹切碎。

### 焦散均值的标定

能量守恒上水面只重新分配光、不凭空造光，所以焦散场的均值必须为 1；而 1/|J| 在 J=0 处发散、没有解析期望，只能由 `ocean.ts` 在初始化时真的跑一帧、回读真实数据算均值再回填成增益，否则换一次谱整幅画的曝光就整体漂一档。`readPixels` 会强制 GPU 同步，运行时不能碰；改了谱形就要重新标定。焦散上限在着色器与 CPU 侧各存一份常量，改一边必须改另一边。

### 焦散调制的守均值形式

焦散场是右偏的，按活度收缩、叠涟漪、倍频混合都必须写成 `1 + (c−1)·k` 这类守均值写法，而不是 `mix` 或直接削减。均值一旦漂移，自动曝光闭环与薄膜按最暗一档定下的 alpha 会一起失准，暗部还会侵占本该放字的那一带。

### λ 的反算来源

λ 决定亮点有多稀疏，σ_lap 是谱的产物、换风速就变，所以 λ 必须由 CPU 按实测 σ_lap 反算后传进着色器，亮暗比才不会随风速漂。太大亮部聚成亚像素噪点，太小整片均匀发亮。

### FFT 链的符号、位反转与 Nyquist

逆变换的 `uSign` 必须取 +1，要的是 e^{+ik·x} 这一支；取 −1 也能出一张「像海浪」的图，只是把图案镜像了，浪与光的方向对不上，光会从错误的一侧斜过来。位反转放在演化那一趟、按自然序读谱写出反转后的位置，因为下一趟的蝶形是 DIT 形式，改蝶形形式必须同时移动它。Nyquist 行与列必须在 CPU 侧清零：那一格是自身的镜像，谱值不纯实会让导数场带出虚部，反过来污染波高。

### 浮点颜色缓冲的降级路径

`createOceanField` 在驱动不支持浮点颜色缓冲时返回 null，调用方必须换成一张 1×1 的常值纹理（斜率为零、焦散为 1）：水会变成一潭平静的水，但辐射传输那一层仍然成立，画面不会瞎。不要把 null 当成致命错误扔出去。

### 唯一的一条颜色管线

水体 pass 只输出线性 HDR，亮部必须真的超过 1；泛光只在它之后，ACES、sRGB 编码与抖动只在 `tonemap.*` 里做，three.js 的色彩管理必须整条关掉。在水体 pass 里就压进 [0,1]，泛光会退化成把整幅画糊一遍；泛光阈值必须落在 ACES 肩部之上、强度压小，阈值一低整幅就发糊，那不是辉光、是没对上焦。泛光在水体曝光之后，阈值因此随自动曝光一起动，这在物理上是对的；承载它的 render target 必须存得住大于 1 的值，8bit 会把高光直接切平，泛光就无从挑起。

### ACES 曲线与 acesInv 的同源

`tonemap.frag.glsl` 里的 ACES 曲线与 `skyRenderer.ts` 的解析反函数 `acesInv` 是同一份数学，闭环用它把屏幕亮度折回场景亮度。改曲线任何一个系数都必须同步改反函数，否则闭环目标会静默偏移，表现只是画面偏亮或偏暗，不报错。闭环的误差必须在 ACES 之前的场景空间里算——拿显示亮度的比值去乘增益，每一步只能推进一点点；曲线是 Narkowicz 的 ACES 拟合，换拟合式等于换闭环的定义。

### 回读时机与画布像素尺寸

`readPixels` 必须紧跟在绘制之后，否则合成器已经把 drawing buffer 清掉；也正因为回读是同步阻塞，canvas 的像素尺寸刻意就是渲染分辨率（由 CSS 负责放大）。不要改成「canvas 满分辨率 + composer 低分辨率」——那样每次探测都要回读整块画布、把 GPU 管线掐停一段可观的时间。探针回报的分辨率必须是像素预算夹过之后的实际值，报预算砍之前的愿望值等于虚报。

### 水面时间的单一来源

`uTime` 同时喂水面着色器的取样和 FFT 波场的演进 pass：波场的形状完全来自 FFT，而着色器取样它的坐标里没有时间项，各自乘各自的系数会让波峰和焦散错开、出现重影。所以「水慢下来」只有一个旋钮（一个累加器乘时间倍率），曝光闭环、探针、指针视差、自适应分辨率照旧用真实时间。每帧的顺序也固定为先跑 `ocean.update` 再 `composer.render`，否则主着色器采到的是上一帧的水面。

### 失败路径与资源生命周期

three.js 拿不到上下文时是抛异常、不是返回 null，所以构造本身要包 try，只做特性检测不够；着色器编译或链接失败也要当成不可用处理，因为那条分支里用户看到的是「背景瞎了」而不是降级，天光渲染器的动态 import 失败同样不许抛出去。降到最低分辨率仍交付不出帧时才是最后一道降级，而它的判据只能是实测帧率，不能拿核数之类的猜。销毁时把 program 与 render target 交给 three.js 回收，别手动 `deleteProgram`——它的程序缓存里仍留着那条记录，万一 canvas 被复用就会拿到一个已删除的 program；异步加载的 await 期间组件可能已被卸载，那之后要靠一个「已卸载」标志退出。

### 涟漪落点与 rayDir 的几何

CPU 侧按同一套 uv 约定与旋转顺序把屏幕点打到水面；打在沙底时落点要沿光的来向退回到上游点。否则环会被光路推偏几米，沙区几乎没有响应。

### 全屏 pass 的 GLSL 声明

GLSL 文件里不能自己写 `#version`——它由 three.js 注入在文件开头。RawShaderMaterial 不替我们声明属性（`in vec3 position` 必须自己写），而 ShaderPass 用的 ShaderMaterial 反过来会自动声明 position/uv 与矩阵、写 GLSL1 即可，重复声明会编译失败。

## 首帧与主题

### 首帧底色与主题镜像

`index.html` 内联块里的首帧底色（由 `--boot-bg-light/dark` 承担）必须分别等于 `main.css` 两处 `--bg-deep`（浅色在前、深色在后），构建期的 `theme-boot` 守卫会读这些锚点校验；应用底色的规则要继续引用它们，改成字面量会让这层保护静默失效；这段 `<style>` 要留在 `<head>` 里、排在 Vite 注入的样式表之前、随 HTML 同一趟到达，并声明 `color-scheme`，否则滚动条与原生控件在首帧还是错的。首帧主题的同步镜像是同一份契约的另一半：`theme-boot.js` 读的键必须与 `useTheme()` 写入的、`storage.ts` 初值读的是同一个，真源在 `logic/themeBoot.ts`，构建校验读那里的字面量，所以 `themeBoot.ts` 必须保持零 import。`.dark` 与 `.light` 两个类要同时维护，`html:not(.light)` 兜底靠后者区分「显式选过浅色」与「没选过」——少切一个，用户显式存了浅色而系统是深色时首帧会被系统偏好翻成深色；`localStorage` 被隐私设置或企业策略禁用时要静默退回系统偏好，不能让首帧脚本抛错。

### 主题模式的异步读出

主题模式是从 `chrome.storage.local` 异步读出来的，挂载那一刻还是默认值，所以必须 watch 住 dark 重推一帧，否则水按浅色算、薄膜按深色算（见过 html 是深色而水还是浅色）。

### 主题过渡的时长与单帧路径

界面颜色、薄膜、暗角必须和水体用同一段过渡时长：CSS 里的时长从渲染器模块的命名空间取、与 `THEME_BLEND_MS` 对齐，不复制数字、也不新建只放常量的模块，否则中段会出现「终点色文字压在起点色水上」的不可读区间。要参与过渡的颜色 token 必须同时用 `@property` 注册成 `<color>` 并列入根部的 transition 清单，漏一个就那一处瞬切；不支持 `@property` 的浏览器退回瞬切，没有副作用。`prefers-reduced-motion` 下时长必须传 0，而且 `setFrame` 之后必须自己补一次 `renderOnce`——那种情况下渲染器只画一帧，没有 rAF 就没有下一帧会用到它。

### 增益的两个变量

闭环的每一步都从 `gainShown`（这一帧真正乘进画面、也是探针量到的状态）出发，而不是从上一轮算出的 `gainTarget`；过渡期间两者不同步，从目标出发等于把同一份修正重复投入，表现就是过冲。`gainTarget` 是阶跃式的目标，`gainShown` 按一个很短的时间常数指数逼近它，所以这段过渡只在阶跃真的发生时才看得见。跨主题要记住的是「曝光 × 增益」这个场景无关的乘积，记增益本身只会记到一个只能当次用的数。

### 薄膜亮度与 CSS token

薄膜颜色的相对亮度写成了常量，必须与 `main.css` 的 `--veil-color-strong` 在两套主题下的值同步；深色侧的上限由最严的那处文字（小字号、`--text-3`）按 4.5:1 反算，改令牌就要重新量。

### 薄膜 alpha 的求解空间

薄膜是 CSS 图层，浏览器按编码后的通道值混合，所以 alpha 必须在编码后的空间里解；在线性亮度上除以一个比值会少给 alpha。探针量在渲染分辨率上、薄膜却按 CSS 像素合成，重采样会让元素边缘的局部亮度再差一点，要留一点余量。

### 压在背景上的文字清单

「有自己的一层」不等于「不依赖背景」——半透明玻璃透出来的就是它自己的背景；往页面里加任何压在背景上的文字，必须往 TEXT_SELECTORS 里加一行，没被量过不等于没问题。

### 文字对比度的计算口径

对比度按元素自己的颜色、字号与累积透明度算：大字号按 3:1、其余按 4.5:1；半透明文字要先按 alpha 与背景合成再算，alpha 低到分母非正时任何背景都救不了。祖先 opacity 不在 computed color 里，必须自己沿链连乘。

### 字色 token 的取值

字色 token 的值按「最差那一行」和真实合成像素量，不按平均或白底算，小字不给大字号折扣。字色与可读性薄膜是一对：把带上那一档字压深能换掉几乎整层薄膜，反之就得让雾洗掉整片画面；深色主题的 `--surface-strong` 不能调亮，因为它就是首字母的底，越白字母对比度越低。改这些值必须重跑对比度审计，并同步检查 `SkyBackdrop` 里的薄膜亮度常量。

### 探针的分位数口径

元素框用 p05/p95 而不是 min/max，单像素极值会被抖动噪声主导；整幅曝光只看分位数，小面积高光（月亮、星点）不许主导设定值，max 只用来说明有这东西。这套口径要与对比度审计脚本一致。

### 两个系统偏好的兜底

「减少动效」下入场编排整条不参与，而不是压缩到极短：组件自己把子树里的入场动画摘掉（用通配加 `!important`，因为子层规则更具体），不依赖 `main.css` 的全局压缩，否则全局规则日后若保留延迟，这些图层会退化成先在起点姿态停一会儿。拖动仍保留「东西跟着手走」，只去掉缩放与旋转；「减少透明度」下玻璃材质塌回实心底，文字的可读性不能靠模糊撑着。

## 磁贴与站点

### 入场时间轴与起波锚点

hero 的第 n 拍与磁贴带的起波锚点都从 `logic/motion.ts` 的节拍派生，`--beat` 由宿主注入、磁贴带取同一常量的倍数，两处各写一份延迟就等于又造出两套时间轴。锚点必须用 setup 里的 `performance.now()` 量，不能用 `onMounted`——hero 的 CSS 动画从首帧起算，两者差一两帧，锚点就会漂到别人的拍子上。延迟要一次性算好存成「磁贴 id → 毫秒」的映射、与挂上动画在同一次渲染里定格，否则 `animation-delay` 一变动画就从头重放；列数从真实布局的 `grid-template-columns` 读，起波之后新出现或撤销回来的磁贴不复用这条波前，要立刻做一次短促落位。

### 入场动画与交互态的属性通道

逐格入场只写独立的 `translate` / `scale` / `rotate`，`transform` 留给 hover 与 active（磁贴抬升、图标放大、按钮按下都在那条通道上）。填充模式用 `backwards` 而不是 `both`：结束值都等于静止值，`both` 会让动画跑完后仍长期压着普通声明，元素常驻层叠上下文，hover 也会被压住。以后新增图层，只有「结束值不等于静止值、且必须持续生效」时才该改用 `both`。

### 延迟期的命中与焦点可见性

入场起点要把 `pointer-events` 写进 from 帧（它可做离散动画），否则延迟期的磁贴是「零像素但可点」，鼠标点在看不见的玻璃上站点照样跳转。焦点不受 `pointer-events` 管，键盘把焦点送进一格时要用 `!important` 把正在跑的动画按到落定态——作者声明的 important 在层叠上高于 CSS 动画；不要改成取消动画，取消会让失焦后从头重播。

### 拖动命中的布局坐标

格子位置一律用 `offsetLeft` / `offsetTop` 量，不能用 `getBoundingClientRect()`：邻居在播 FLIP 位移或入场动画时，rect 会带上动画里的位移，手指没动命中判定就先跳到隔壁格，落位动画也会朝错的地方收。`tile-grid` 的 `position: relative` 是这套坐标的依赖——它必须是格子的 `offsetParent`。

### 拖动顺序的本地副本

拖动期间只改组件内的本地顺序，松手才写一次 storage，否则每滑过一格都要落一次盘。落盘前要按 id 重新认出「我在哪、要去哪」，而不是沿用下标——storage 可能被别的标签页增删过，下标会错位。

### 手势的输入精度分类

只有 `pointerType === 'touch'` 算「手指」，触控笔与鼠标同属精度输入。手指在任何模式下都要先按住才起拖、卡片还要抬到指尖上方；鼠标与笔只在非「整理」模式下等长按——整理模式里磁贴不是链接，没有误打开站点的风险。

### 「拖动」的判据与点击补偿

判定成拖动只能是真的挪过窝或真的换过格子；按住但没挪窝仍是慢点击，照常打开站点，按得足够久又一直不动则视为「拿起又放下」、不导航。真正拖过之后只抑制被拖那一格紧随其后的 click——用户拖完马上点别的图标是正常的。

### 拖动期间浏览器默认行为的兜底

`touch-action` 在手势开始后再改就来不及了，长按成立后只能自己拦 `touchmove`（`passive: false`）；系统右键菜单、原生 `dragstart`、文本选中与触屏高亮也要一并挡掉。拖动开始后还要监听 window 的 blur 与 visibilitychange——切窗口或切标签页之后指针事件不会再来，不收拾就会把拖动卡在半空。自动滚动直接滚 `document.scrollingElement`，因为三个宿主页面都是整页滚动；哪天改成内层滚动容器，这里要跟着改。

### 键盘模型的宿主开关与 Alt 保留组合

网格的 roving tabindex、方向键导航与 Alt 快捷键都由宿主显式开启，设置页与侧边栏不传这些开关，否则预览会改掉用户的原生 Tab 顺序、或把用户困在预览里；网格里 Tab 只进出一次、方向键换格，整理模式下磁贴面退出 Tab 顺序、只有当前格的四个按钮可 Tab。搜索框把 Tab 征用为「切引擎」之后，必须保留 Esc 三级出口（关列表、清输入、交回页面开头）与 Alt 区块快捷键作为离开路径，对话框打开或拖动进行时 Alt 导航与提示要整体让路。Alt 组合会先被浏览器截获，菜单、地址栏与切换标签页占用了一批 Alt 开头的按键，新增提示键位时必须避开这些保留组合，否则提示还在、按键却到不了页面。

### 首屏焦点落点

初始焦点静默落在搜索框：要用 `preventScroll`，否则聚焦会把带入场位移的搜索框滚进视口，在矮视口上多滚一截；同时不能画高亮，因为输入框的 `:focus-visible` 在脚本聚焦时恒为真，只能由组件状态区分「页面摆上去的焦点」与「用户自己走过来的焦点」。键盘用户第一次从页面外进入时，只有 `relatedTarget === null`、落点带 `:focus-visible`、且落点在搜索框之前，才把焦点交给搜索框，并且只接管一次——否则页眉和问候语永远进不了原生 Tab 顺序。

### 引擎环的连续相位

环的角度每按一次 Tab 只走一格，当前引擎始终落在「基础角度 + 相位」的锚点上；不能每次从引擎下标重新取模，否则从最后一颗绕回第一颗时，CSS 会在两个相差近整圈的角度之间插值，那颗气泡会反向绕远路。直接点选或外部同步换了引擎时，只把相位对到最近的等效角度；环上气泡的 DOM 顺序固定按引擎目录，不按角度排序，位置只由 `transform` 过渡。

### 默认打开方式与 target

磁贴与搜索提交默认在当前标签页打开，与 Chrome 地址栏一致；设置页与侧边栏这类辅助界面才显式要求开新标签页，否则同页跳转会把宿主自己顶掉。同标签页时 `target` 要整个省略而不是写 `_self`，这样 Ctrl/⌘+点击、中键点击仍是浏览器原生的新标签页动作；也不要加 `<base target="_blank">`，那会让页内链接行为分裂。

### 隐藏、禁用与对话框的焦点

需要 Tab 到达的排序按钮只能用 `opacity` 藏起来（配 `pointer-events: none` 防触屏误点），不能用 `visibility: hidden` 或 `display: none`——后者不进 Tab 顺序，`:focus-visible` 的显形规则会变成死代码。到头方向的禁用要用 `aria-disabled` 加提前 return，不能换成 `:disabled`：禁用按钮拿不住焦点，键盘用户把磁贴挪到头后焦点会掉回 body。对话框打开时要记住触发前的焦点元素、关闭后还回去，并把 Tab 限制在面板内循环；拖动排序完成要经 `aria-live` 播报新位置，否则读屏用户不知道刚才那一下去了哪。

### 键帽提示的可见性前提

按住 Alt 的提示只为至少一半可见、且没被隐藏的目标出现；目标被挤出屏幕时仍弹出键帽，提示就成了无根的东西。提示必须 Teleport 到 body 并按实时 rect 计算（打开、改窗口、滚动时重算），否则会被父级的 `overflow` / `z-index` 裁掉；它只是视觉补充，整体 `aria-hidden`——读屏念按钮自己的 `aria-label` 就够。

### 图标缓存的键与失败降级

图标缓存按站点源（scheme://host:port）记，而不是按完整页面地址；但 Chrome 取图看的是具体页面地址，同一站点不同路径可能一个有图标、一个返回占位图，所以「没有图标」的结论永远不能覆盖已经确认的真图标，展示侧判定失败时也要保留真图标并刷新时间戳。写入与展示两侧都必须基于刚重读出的最新缓存判断，不能拿页面加载时的旧镜像做决定——每个扩展页面都持有一份内存镜像，后写的页面若整份覆盖会抹掉另一个页面刚写进去的真图标。图标缓存是增强而不是依赖：隐私设置、企业策略与配额都会让 `localStorage` 的访问或写入抛异常，所有失败必须吞掉并退回现场取图加首字母；storage 内容可能被手改或写到一半，解析时必须逐条校验、把脏条目当作不存在；容量要同时按条目数与总字节兜底，只限条目数不够，条目上限乘单条上限会远超 `localStorage` 配额。

### 图标接口的权限与同源

站点图标走 MV3 的 `/_favicon/` 接口，manifest 必须声明 `favicon` 权限，地址要用 `runtime.getURL` 拼、不能写死扩展 URL。指纹判定依赖该接口与扩展页面同源才能读取 canvas 像素；换成第三方 favicon 源会污染 canvas，读取抛异常后只能退回首字母。

### 深浅两套磁贴配色

浅色与深色两套磁贴配色必须按下标一一对应：同一个站点切换主题时应当只翻明暗、留在同一色系，而不是换一个颜色。新增或删除任一色板时两边要同步改动，否则同站会在换主题后变色。

## 存储与迁移

### 存储键与脚本的直读契约

storage 里存的是序列化后的字符串而不是结构化对象，`scripts/*.mjs` 会绕过应用代码直接按同一组键读写原始值；改键名、前缀或序列化方式时两边必须一起改，否则脚本会静默读写到空数据。`meridiem-` 是发布前旧名留下的冻结技术前缀，不随品牌名（子午 Ziwu）改动；旧前缀的键只出现在迁移兼容层里，新增键一律用当前前缀，不要把两代键名混用成两套数据源。品牌与键名的决定见 [ADR-0007](adr/0007-品牌名定为子午-Ziwu.md)。

### 预置站点的写入一次性

预置站点只在 storage 里没有快捷方式键时写入一次；键存在但值是空数组，表示用户主动删光了磁贴，必须保持为空。页面挂载时不能做「补回预置站点」的合并，否则用户删掉的磁贴会复活成预置站点。

### 站点地址清洗的单一真源

导入、导出、读 storage 三条路径必须共用同一套站点清洗，否则会出现「能存进去但读出来被过滤」的站点，或同一站点在合并导入时重复。只放行 http 与 https 是安全边界，不要为了兼容其它协议放宽；整理用户输入时要把 `host:port` 当主机端口而不是协议，本地开发地址默认走 http。

### 备份文件的身份标识与版本号

备份文件必须带格式标识与整数版本号：只有新增可选字段才保持版本号，改变已有字段含义或删除字段时必须升版本并在解析处按版本分支，否则旧版本会静默误解新文件。格式标识 `meridiem.backup` 是冻结的文件身份，不随品牌名改动；改它等于换一种格式，必须按版本兼容处理。高于当前版本的备份要直接拒绝并提示升级，不能降级读取；备份里的主题取值集合必须与 storage 的主题类型同集，不许在备份层收窄或改名。

### 备份缺失项的含义

备份里某个设置项为 null 表示「这份文件没带这一项」，导入时必须保持本机原值，不能当清空处理。在能通过身份校验的备份里，只有站点与设置全空才算无效备份；把缺失当清空会让一份手工删过字段的备份抹掉用户设置。

### 备份中站点 id 的归属

备份只存站点名称与网址，不存 id：id 属于导出它的那台机器。合并导入时直接采信会出现两条同 id 的磁贴，之后删除一个会连带删掉另一个、排序也会错位，所以写入本机 storage 时必须现造 id。

### 问候语长度上限的唯一真源

问候语的长度上限只有 `GREETING_MAX_LENGTH` 一个真源，设置页输入框与备份导入的截断都读它。只改输入框的 `maxlength` 不够——导入可以绕过 UI 限制写入超长值，之后编辑框显示不全。

### 搜索引擎 key 的持久化约束

搜索引擎的 `key` 是持久化标识，会写进 storage，不能随显示名一起改；旧 key 找不到时查询会静默回退到默认引擎。导入备份时必须在当前目录里校验这个 key，目录里没有就忽略并告知用户；新增引擎还要给出深色主题变体，品牌色多是为白底设计的。

### 覆盖导入的破坏性边界

「覆盖」模式会把本机磁贴整份替换成备份里的，备份里没有的站点会被删除；「只带设置、没有站点」的备份也能通过解析，按覆盖导入会清空所有磁贴。UI 必须在提交前把将删除的数量或「全部清空」讲清楚，不能只靠单选按钮的通用说明。

### 源码与个人站点的隔离

默认站点清单只放无需登录、与个人账号无关的公开首页；私人书签、内网地址、带租户或账号参数的深链一律不得进源码——仓库内容会被打包进扩展产物并推到远端。个人站点只经设置页的导入导出在本机 storage 里流动，这是个人数据唯一的跨机器通道。

## 构建与验证工具

### 验证脚本加载的生产产物

验证脚本直接加载 `extension/`，而 `pnpm dev` 会把 `extension/dist` 覆盖成指向 localhost 的桩，此后脚本会死在连接被拒、页面上只剩「Vite server did not start」——这是产物态问题，不是功能坏了。判别方法是看 `extension/manifest.json` 的 CSP 里有没有 localhost；同一份产物也用于 README 配图，用开发态截出来的图会「看起来正常但和线上不一样」。

### 扩展 storage 的写入编码

对象与数组型键存的是 JSON 字符串，字符串型键原样存；外部脚本只能用原始读取处理字符串键，一律 `JSON.parse` 会把合法值解析坏。读对象键之前先确认它在产品侧确实是序列化存储的。

### 首帧主题镜像的脚本采样

截图脚本只写 `chrome.storage.local` 时，测到的是「装完或更新后第一次打开」那条路径——首帧不等异步 storage 返回，镜像也得由脚本补种，而且只能用扩展自己的页面写（同源）。镜像缺失时首帧只能按系统配色偏好兜底，别把「异步键写过了」当成首帧已经覆盖。

### 持久化上下文的启动参数

`launchPersistentContext` 的 viewport 与 `deviceScaleFactor` 只在启动时生效，之后 `newPage()` 的同名参数会被静默忽略并退回默认尺寸。按 CSS 像素乘设备像素比算出的采样矩形会整体错位，却不会报任何错。

### 天空采样的稳态判据

自适应分辨率与曝光都在爬坡，必须等控制器自报稳态后再采样；「连续若干次采到相同缩放比」太松，控制器两次调整的间隔大于采样间隔时会在爬坡途中被判成稳。曝光闭环比分辨率慢得多，收敛之后还要再给一段沉降；慢机器上结束时画面确实会软一些，这是可接受的代价。

### 对比度的取数方式

天空、玻璃、暗角这些效果只存在于合成后的像素里，读计算样式看不见画布，所以背景上的对比度必须从截图取像素；纯 DOM 上的对比度要把前景透明度与多层背景逐层叠加、把渐变里的颜色也算成候选背景并取最坏的一层。整屏图的像素分量是千万级，统计必须在页面里算完只回传统计值——塞进求值返回值会传不回来，表现为统计恒为 0。

### 像素时间线的采样位置

把 WebGL 画布画进 2D 画布读取这一步，必须在同一帧渲染之后、合成之前执行，否则绘制缓冲已清空、量到的是黑。采样器的逐帧回调要挂在渲染器之后（渲染器先初始化），并把画面降采样以压低读回成本。

### 时间线对齐与首帧白闪的归因

页面里的 `performance.now()` 与 Node 的 `Date.now()` 不是同一原点，切换或起波时刻只能在页面里取；CDP 的单调时间要用性能指标里的时间戳配合一次往返换算成墙钟，动画的 `startTime` 走文档时间线，它和 `performance.now()` 的差值要记下来，差大了按 `startTime` 推出来的时刻就不可信。录屏必须在导航之前开启，否则白屏那几帧根本没被录下来；白闪只算本页该背的那段，从本页首次绘制起算，横跨明暗两套主题的判据只能是「与终态底色是否同类」，用「亮底帧」当结论在浅色场景会全盘失效。

### 图标出现条件的双重依赖

「图标能不能出现」同时取决于 Chrome 图标库（要真的访问过站点才种得上）和页面里的图标缓存（含否定结论与保鲜期）。判定有没有真图标要拿一个肯定不存在的域名标定出的占位图指纹去比对，不能靠「看起来像首字母」猜；「图根本没加载出来」必须与「拿到占位图」分成不同结论。缓存键与探测地址要与产品侧逐字一致（脚本刻意不 import 产品代码，避免把打包器别名解析带进纯 Node 进程），而取不到图标是预期分支，不能算失败。

### 跨轮对照的采样口径

帧率、逐格轨迹、胶片条这些数字只在同一设备像素比、同一图标模式、同一「减少动态效果」设定下才可比；每轮把口径写进产物，比数之前先看这里。小图标只有几十像素，整屏帧里读不出它的姿态，要看图标得单独打一张高像素比的单格特写。

### 后台报错与扩展上下文的取证

页面的报错监听看不到 service worker，后台报错要从 service worker 上下文里捞；它是异步启动的，读一次拿不到不代表没有。起上下文后还必须先验证新标签页改写真的接管了，否则整批数字会静默变成浏览器自带新标签页的。

### 模拟从浏览器进入页面的焦点起点

Chrome 会把顺序焦点导航的起点留在上一次聚焦的元素上，直接 blur 之后下一次 Tab 会从搜索框往后走，正好把要测的问题遮住。把 body 临时变成可聚焦元素再聚焦，起点才落到文档开头；这种方式下焦点进入事件的来源元素为空，产品逻辑正是靠这条判断的。

### 工具栏图标与侧边栏的接线

扩展默认不接管工具栏图标，点击图标走 popup；要让 Chromium 的图标直接打开侧边栏，需要显式打开开关并调用 `sidePanel.setPanelBehavior`。Firefox 的侧边栏走 `sidebar_action`，Chromium 走 `side_panel`，两套 manifest 声明必须分开生成，`sidebar_action` 在 Chromium 不生效。
