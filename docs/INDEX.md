# 文档索引

代码说明不了的事只有四个落点。**同一条事实只写一处**，别处引用、不复述。

## 按判据选落点

| 你手上的是 | 写进 | 判据 |
| --- | --- | --- |
| 口径与不变量：对外承诺、数据格式、单位与色彩空间、跨文件必须一致的键、违反后不报错只是悄悄错的性质 | [CONTRACTS.md](CONTRACTS.md) | 改坏它不会有报错，只会有错的结果 |
| 架构取舍：模块怎么切、为什么这么切、否决了哪种做法 | [DESIGN.md](DESIGN.md) | 读代码的人会问「为什么不换个做法」 |

| 其余一切 | 代码本身 | 能从命名与结构读出来的，一律不写 |

## 写作口径

1. **不抄会被调参改掉的现状。**「现在是 320ms」这类句子每次调参都会变假。要留证据就钉成历史：「上一版 520ms 里有 375ms 几乎不动」。
2. **不抄别处声明的值。** 写名字（`--dur-enter`、`TILE_WAVE_ROW`）并指向声明处，不要把值搬过来——搬一份就是多一份会过期的副本。
3. **改数字先 grep 文本形式。** 动任何一个数之前，先搜 `400ms`、`13.3%`、`760` 这类文本形式，把复述它的句子一起改掉，包括其他文件里的。
4. **一条只写一处。** 需要第二次提到时写「见 X」，不要重述。
5. **写不变量时写清违反的代价。** 是报错，还是悄悄错，读者要靠这句话决定要不要冒险。
