# 引入 three.js 只买后处理

- 日期：2026-10-19
- 状态：已采纳

## 背景

水面（波谱、体积步进、Snell 窗、菲涅耳、焦散）是几百行自写 GLSL，而 three.js 的 Water2、Reflector 两个 helper 都默认相机在水面之上，水下仰视根本没有实现，换不掉。真正缺的是后处理：焦散高光必须溢出到邻近像素才有「亮」的感觉，单 pass 做不到，而这是这类画面最容易被一眼看出差距的地方。自制泛光被否决。

## 决定

引入 three.js，但只买后处理管线（合成器与泛光），连同尺寸管理、上下文丢失处理与程序缓存；水仍然自己写着色器。

## 后果

three 成了唯一的运行时依赖，包体积与升级节奏跟着它走；后处理链的几个前提也一并锁死：承载泛光的缓冲要存得住大于 1 的值、泛光排在曝光之后、色彩管理整条关掉（见 CONTRACTS.md）。换回自研后处理要重做的不是泛光那一步，而是探针读取的位置与线性 HDR、ACES 之间的边界。

不要因为「水不够好看」去打 three 那几个水面 helper 的主意，那条路在这个机位下不存在；同理，删泛光也不是删一个 pass。
